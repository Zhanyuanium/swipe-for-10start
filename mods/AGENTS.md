start-menu-legacy-swipe.wh.cpp: the shipping mod, `StartMenuExperienceHost.exe`. Raw HID touch/pen decode (RIDI_PREPARSEDDATA + HidP_GetUsageValue), axis-aware state machines on a worker thread for both dismiss (drag inside the menu) and reveal (edge swipe; anchored to the panel trailing edge), `Progress` composition expression, dismissal by playing one damped-spring settle and then tapping `VK_LWIN` (down 60 ms, up) at the end of it; that tap is the shell's own Start toggle, so its key handler performs `CStartExperienceManager::Hide` and the next Windows press opens. One spring generator serves all four outcomes; `AnimationStyle` picks only its parameters: `Windows 11` (default) period 0.102 s / damping 1.72 / 253 ms, fitted to the native Quick Settings flyout on this machine, and `Windows 10` period 0.25 s / damping 0.9 / 221 ms. Both start at `GestureStartSpeedPercent` (default 100) of the finger's release speed over the travel left, so a release from a hold starts at zero speed and a flick continues; the duration is five time constants of the spring's slowest root, so the overdamped Windows 11 set still lasts 253 ms. At the release the mod stamps `close-mode.txt` with `gesture=0`; the tap is armed for the end of the settle, and one pull-generation check drops it (the stamp then says `cancelled`) if a new pull began first. No request file, no bridge-hide worker, no re-arm tap. The release is detected by an 18 ms silence measured with `QueryPerformanceCounter` on a 5 ms `CREATE_WAITABLE_TIMER_HIGH_RESOLUTION` idle tick (`WM_TIMER` ignores the 1 ms `timeBeginPeriod` request on this build). Hooks `StartUI::App::PrepareRootElement` (hardcoded RVA) for the root and an experimental `SplitViewFrame::OnGlobalAnimationRequested` hook (`anim=` debug switch, off by default because that request also presents the panel). The 600 ms post-close suppression ends at `win close observed`, so a Win press after the hide opens a visible panel. The debug channel takes `retract` for a Windows-key close.
msgprobe.wh.cpp: diagnostic. Hooks `GetMessageW`/`PeekMessageW`, logs `WM_POINTER*` and mouse messages. Established that the queue carries only ENTER + DOWN and then `WM_POINTERCAPTURECHANGED`.
inputprobe.wh.cpp: diagnostic. Raw HID listener plus a `CoreWindow`/`SystemUserAdapterWindowClass` WndProc subclass. Took the digitizer stream first and proved per-frame reports are readable. Must not run beside the shipping mod: Raw Input allows one sink per usage per process.
start-menu-touch-gesture-bridge.wh.cpp: `explorer.exe` bridge. Hooks `CStartExperienceManager::Show/Hide` (`Hide` is `HRESULT (void*, uint32_t)`, RVA `0x3C5960`). A Hide inside 800 ms of a `gesture=0` stamp is the Start side's own tap, sent after its retract, so it runs at once (`hide passed (gesture)`); a stamp of `cancelled`, a stale stamp, or a second Hide under the same stamp is a keyboard close: the bridge writes `retract=1` to `debug.txt` and waits 350 ms synchronously before the original. No worker, manager pointer, timer, dispatch window or re-arm tap remains; every path calls the original. Publishes the taskbar edge gesture handle and state from `twinui.pcshell.dll` into shared memory (not read by the shipping mod); refuses to hook on a build mismatch.
start-menu-touch-gesture-probe.wh.cpp: Phase 0 probe that located `TouchEdgeGestureProcessor` and `ReportEdgeGesture`.
start_gesture_shared.h: shared-memory contract shared by the bridge and its consumer; layout must stay in sync with both.
