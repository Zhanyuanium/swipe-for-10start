start-menu-legacy-swipe.wh.cpp: the shipping mod, `StartMenuExperienceHost.exe`. Raw HID touch/pen decode (RIDI_PREPARSEDDATA + HidP_GetUsageValue), axis-aware state machines on a worker thread for both dismiss (drag inside the menu) and reveal (edge swipe; anchored to the panel trailing edge), `Progress` composition expression, dismissal by retracting on one 260 ms curve (shortened only by flick velocity) and then writing `hide-now.txt`, which the explorer-side bridge turns into the shell's own `Hide`. The release is detected by an 18 ms silence measured with `QueryPerformanceCounter` on a 5 ms `CREATE_WAITABLE_TIMER_HIGH_RESOLUTION` idle tick (`WM_TIMER` ignores the 1 ms `timeBeginPeriod` request on this build). Hooks `StartUI::App::PrepareRootElement` (hardcoded RVA) for the root and an experimental `SplitViewFrame::OnGlobalAnimationRequested` hook (`anim=` debug switch, off by default because that request also presents the panel). Both close paths share one deferred request slot (`RunPendingClose`); a pull generation recorded at scheduling drops it as `close request dropped kind=...`, so a cancelled close never reaches the shell. A failed write falls back to the old `VK_LWIN` tap. A gesture close also stamps `close-mode.txt` for the bridge; the debug channel still takes `retract` for a Windows-key close.
msgprobe.wh.cpp: diagnostic. Hooks `GetMessageW`/`PeekMessageW`, logs `WM_POINTER*` and mouse messages. Established that the queue carries only ENTER + DOWN and then `WM_POINTERCAPTURECHANGED`.
inputprobe.wh.cpp: diagnostic. Raw HID listener plus a `CoreWindow`/`SystemUserAdapterWindowClass` WndProc subclass. Took the digitizer stream first and proved per-frame reports are readable. Must not run beside the shipping mod: Raw Input allows one sink per usage per process.
start-menu-touch-gesture-bridge.wh.cpp: `explorer.exe` bridge. Hooks `CStartExperienceManager::Show/Hide` (`Hide` is `HRESULT (void*, uint32_t)`, RVA `0x3C5960`), caches the manager pointer, and runs one worker that polls the Start mod's `hide-now.txt` every 20 ms; a request is executed as the original `Hide(manager, 1)` on the shell's UI thread through a message-only window created there. That `Hide` does not update the shell's Start toggle, which lives in the key handler, so the worker sends one Windows tap 120 ms later (`hide toggle rearmed`) to re-arm it; the tap is invisible while the menu is closed. A Windows-key close is still delayed up to 350 ms after writing `retract=1` to the Start mod's `debug.txt`, which turns it into a slide-out; a `close-mode.txt` stamp younger than 800 ms means the hide belongs to a gesture close whose retract already ran, so it is not delayed. Every path calls the original; returning `S_OK` without it desynced the shell's Start toggle. Publishes the taskbar edge gesture handle and state from `twinui.pcshell.dll` into shared memory (not read by the shipping mod); refuses to hook on a build mismatch.
start-menu-touch-gesture-probe.wh.cpp: Phase 0 probe that located `TouchEdgeGestureProcessor` and `ReportEdgeGesture`.
start_gesture_shared.h: shared-memory contract shared by the bridge and its consumer; layout must stay in sync with both.
