start-menu-legacy-swipe.wh.cpp: the shipping mod (0.24.0), `StartMenuExperienceHost.exe`. Raw HID decode from `RIDI_PREPARSEDDATA` + `HidP_GetUsageValue`: the report ID comes from the report's first byte when the device declares report IDs (`RAWINPUTHEADER::wParam` is only `RIM_INPUT`/`RIM_INPUTSINK`); a report whose ID carries no contact field at all is ignored as unrelated, distinct from `hid decodefail`; every candidate slot's `TipSwitch`/`InRange`/X/Y is decoded before a contact is chosen; the tracked `(device, collection)` wins, proximity to the last raw position only picks a new contact, and only that slot's declared tip-up or in-range clear ends it (a count-only lift report says nothing; the 18 ms idle ends the contact with `src=idle` and forgets the identity); a device with neither tip nor in-range usage keeps the count/position path and logs `coordpath=1`. Axis-aware dismiss and reveal state machines on a worker thread drive `Progress` through one composition expression. One damped-spring settle serves all four gesture outcomes and the keyboard open; `AnimationStyle` picks only the damping — `Windows 11` (default) 1.72, fitted to the native Quick Settings flyout on this machine, and `Windows 10` 0.9 — and `GestureStartSpeedPercent` (default 100) scales the component of the finger's end speed toward the target: the widest eligible window of the last reports (8-30 ms), projected onto the settle direction and divided by the travel left, so a hold reports `vel=0.00`; 100 % is that component, and the curve's own end-value scale (about 0.993) divides the whole motion, so the seam differs from it only by that scale (about 1.007). The commit test keeps the whole-gesture average and the 20% (10% on a vertical axis) travel; only the settle's seam reads the end. The duration is that travel at 2.2 DIP/ms clamped to 160-520 ms, and the curve is scaled by its own value at `T`, so the landing has no step. `TakeProgressNow()` is the only reader that turns the animation's recorded base — its target — into a position, and one close-ownership helper serves both close families: it reads the mute from the contact latch and either gesture family before either owner is cleared, so a held reveal is muted too, and the open publisher writes the cancelled kind with every new open generation so no `tapped` stamp survives into the next menu. Axis, `Distance`, the panel rect with its derived trail, the XAML origin, the work area, the monitor and the open generation are one `GestureGeometry` snapshot behind an `SRWLOCK` (the UI thread is the only writer and holds it exclusively for one struct assignment; a reader tries shared and answers its last whole copy on contention), and a snapshot from an obsolete layout is rejected for a new gesture; a `SizeChanged` under a contact defers its measurement. One idempotent measurement request per open (the layout watch's second pass or the 400 ms deadline) carries a request id and an epoch; the panel publish re-checks id, epoch, axis and travel, and panel ownership at commit; the scroller commit re-checks id, epoch and panel ownership; and the previous rect is carried over only when that whole identity matches. The scroller cache is Unknown/Nothing/Scrollable: only `Unknown` defers, `Nothing` is a completed negative search, an incomplete one stays `Unknown` and retries with `scroller retry why=... gen=...`, and a positive candidate commits even when another branch was unreadable. `PrepareRootElement` is gated on `StartUI_.dll` exactly 10.0.22621.3733 plus the prologue and its `E8` target; the `OnGlobalAnimationRequested` hook is installed on every load and passes through (`anim=1` default, `anim=0` drops the open request). The close record is three publishes of one seqlock record — plan, `tapped` immediately before the `VK_LWIN` tap, cancelled — and the open generation binds a bridge `retract` request to its menu. Unload is prerequisite-driven: the stop event exists before any thread starts (without it no raw-input thread is created and the mod logs `hid thread not started (stop event unavailable)`), the input thread watches it in its 10 ms message wait, the module-scan thread waits on the same event, and the 60 ms Windows tap waits on it and always releases the key. Unload stops the module-scan thread (10 s wait), sets the event, waits 10 s for the input thread, revokes every XAML delegate on the UI thread, drains an already-dispatched settle completion, then frees composition and the IPC view; a thread or callback that misses its wait leaves every resource in place and logs `unload residual=...; process must restart to finish unloading`.
start-menu-touch-gesture-bridge.wh.cpp: `explorer.exe` bridge (0.11.0). Hooks `CStartExperienceManager::Show/Hide` (`Hide` is `HRESULT (void*, uint32_t)`, RVA `0x3C5960`). A Hide on an unconsumed `tapped` close record inside its 800 ms window is the Start side's own tap and runs at once (`hide passed (gesture)`), but only when the stamp is newer than the attach watermark and not older than the newest open tick it read; a plan, a cancelled record, a stale record or a second Hide under the same stamp is a keyboard close. A fresh stamp is correlation, not proof of cause. That path publishes the `retract` request bound to the open generation it saw and a 700 ms deadline, waits up to 100 ms on the plan event for the answer, holds the original synchronously for that settle plus 30 ms (`hide delayed reason=... retract=... lead=...`), falls back to 560 ms for the sentinel or no answer, then marks the request done. No worker, manager pointer, timer or re-arm tap; every path calls the original. Publishes the taskbar edge gesture handle and state from `twinui.pcshell.dll` into shared memory (not read by the shipping mod) and refuses to hook on a build mismatch.
start-menu-touch-gesture-consumer.wh.cpp: diagnostic consumer (0.1.0), `StartMenuExperienceHost.exe`. Maps `Local\WindhawkStartGestureShared` read-only and logs the bridge's state/handle transitions from a reader thread; it changes no UI, so it verifies the explorer→Start publication without the animation.
start-menu-touch-gesture-probe.wh.cpp: Phase 0 probe that located `TouchEdgeGestureProcessor` and `ReportEdgeGesture` in `twinui.pcshell.dll`.
msgprobe.wh.cpp: diagnostic. Hooks `GetMessageW`/`PeekMessageW` and logs `WM_POINTER*` and mouse messages; established that the queue carries only ENTER + DOWN and then `WM_POINTERCAPTURECHANGED`.
inputprobe.wh.cpp: diagnostic. Raw HID listener plus a `CoreWindow`/`SystemUserAdapterWindowClass` WndProc subclass; it took the digitizer stream first and proved per-frame reports are readable. Must not run beside the shipping mod: Raw Input allows one sink per usage per process.
start_gesture_shared.h: the bridge's `Local\WindhawkStartGestureShared` contract (`StartGestureShared`, a seqlock over state, edge, gesture handle and points); read by the consumer probe, not by the shipping mod.
swipe_ipc_shared.h: the v2 channel contract shared by the Start mod, the bridge and `tools/ipc.ps1`: `SwipeIpcState` (672 bytes, every field pinned by an `offsetof` assert), one seqlock per record, the claim/ready init handshake, the close record with plan/tapped/cancel, the open generation and the retract request/plan pair. `SwipeIpcOpen` may wait up to the whole 550 ms budget, so a young claim is abandoned inside the call; `SwipeIpcReadOpen` refuses generation 0 with `ERROR_NOT_READY`; `tools/ipc.ps1` is the only command publisher and takes the mutex; a fresh stamp is correlation, not proof of cause.
