The measurements here are single runs on the same machine: 2880x1800 physical at 200% scaling (1440x900 DIP), so 1 DIP = 2 px. The captures were taken with the taskbar on the left, then on top, where the native-flyout and settle runs were made; the machine now runs the bar docked on the left (`axis=0`, trail 1053 DIP, `distance` 1392 DIP), so a capture's placement can differ from the current layout. Each file's header names the placement it saw. Read a file's comments first; where the capture method changed, the comment says which loop produced it. One local build output is not a member of this roster: `inputprobe.dll` is compiled from `mods/inputprobe.wh.cpp`, `*.dll` is in `.gitignore`, and the file can be rebuilt.

cursor-follow.csv: `probe_cursor_follow.ps1`'s `ms,x,y` cursor samples in physical pixels, taken every ~8 ms during an injected drag. The cursor is suppressed for the whole contact: all 238 samples of this run are the same point (1834,870), and a move shorter than the polling interval would not appear.
gesture-shared.csv: a historical dump of the explorer-side gesture mapping that the retired gesture publisher wrote (`tick,magic,seq,state,edge,src,prov,...`). State 2 is a committed edge gesture; the fields are the v1 layout of that record. Sampling is ~30 ms, so a transition shorter than that is missed. The publisher and its reader were removed in 0.7.0; the file stays as Phase 0 evidence.
native-flyout-open.csv: the native Quick Settings open, `t_ms,dy_px,d`; `t` runs from `ControlCenterWindow` becoming visible, `dy_px` is how far the content still sits above its settled place, and `d = 1 - dy/1156` normalises to the 578 DIP travel. Captured with the earlier loop, which stamped `t` after the `BitBlt` and its copy, so each time is late by that read-back (a few ms); frames are ~9 ms apart.
native-flyout-close.csv: the same capture for the close, but `t` counts from the window hiding, so every sample is negative and the fit needs `--time-offset` with that run's key-down time; it shares the open file's serialised-time bias.
settle-trace.csv: the shipped mod's settle, `style,held,t_ms,edge_px` for the win11 and win10 runs of the same half-open hold release. Produced by the inline loop in `tools/settle_track.ps1` at commit `604402f`, whose clock starts when the UP injection returns and which stamps each `t` after the `BitBlt`, before the read-back into the managed buffer: the two offsets push opposite ways, so the net bias is the `BitBlt`'s copy time minus the UP call's own time, with no fixed sign. The current tool stamps before its `BitBlt` and takes t=0 immediately before the UP, so a rerun does not reproduce this column. `edge_px` is the panel's bottom edge; the presented content can be one compositor frame old, so an edge reading lags `t` by up to one interval.
panel-edge-wintap-1.csv, panel-edge-wintap-2.csv: `tools/panel_edge_track.ps1`'s plain Win open-then-close trace on the left docked bar, `t,tc,edge_px,edge_dip,progress`. `t` is the capture instant stamped before its `BitBlt`, `tc` the milliseconds since the close tap, `edge_px` the panel's trailing edge (2105 px at full open against `trail` 1053 DIP x 2), `progress` the mod's own `RevealProgressDip` mapping. The visible series stops at 98-127 px because the window is cloaked before the last 48 DIP reach the bar; those samples carry `-1`, and the file never shows progress 0. The capture period is ~14 ms and a frame can lag its stamp by one compositor interval.
panel-edge-wintap-pull-1.csv, panel-edge-wintap-pull-2.csv: the same run with one qualified 25 DIP band pull injected at `tc` 150, through `touch_common.ps1`. This is the interruption baseline: every retract landmark stays within 14 ms of the plain runs and no sample reverses or plateaus, so a pull does not abort a Win close. The panel is visible again at `tc` 710/736, which the mod logs as the release record's reopen after the landing, not a live takeover.
panel-edge-interrupt-pull-1.csv: `tools/panel_edge_track.ps1` with a qualified 25 DIP band pull at `tc` 150 against a build that can abort an armed close. The retract stops at 1996 px (progress 0.962) between `tc` 265 and 313 and is back at 2105 px by `tc` 463 with the menu open; the same millisecond carries `exec cancel request target=24 reason=pull` and `reveal takeover ... live=1`. The pre-change pair above is the same sequence without the abort.
panel-edge-interrupt-wintap-1.csv: the same harness with a second Win tap at `tc` 150. The retract stops at 2045 px (progress 0.979) at `tc` 208 and is back at 2105 px by `tc` 363; `intent open cancel from=0.976` and `exec cancel seq=38 target=36` are the press's cancel. Its `SUMMARY min=`/`start=` belong to the setup close, not to the marked run.
panel-edge-p1-early-1.csv: the ownership change (P1) with a band grab at `tc` 150 on the bottom auto-hidden bar: `grab=taken`, `live=1` from 0.931, the edge reverses at 692 px of an 1704 px retract and ends fully open. Same harness and layout as the two interrupt files above.
panel-edge-p1-refused-1.csv: the same harness with the grab's qualification arriving after the close's settle (`tc` 400): `grab=refused reason=offsurface`, `win close observed muted=1`, no reopen and no show. The edge runs monotonically to the 1704 px entry edge and stays there, which is what a landing that adopts no finger looks like.
panel-edge-p2-early-1.csv: the one-take transfer (P2) with a band grab at `tc` 150: one `motion sample caller=pull` at 0.930, `reveal takeover ... live=1` binding to it, the edge reversing at 677 px of 1704 and ending fully open. The same harness and layout as `panel-edge-p1-early-1.csv`.
panel-edge-p2-late-1.csv: the same harness with the grab qualifying at `tc` 400, after the close landed: `grab=refused reason=no-close`, no reopen, no show, menu closed. Shows the refusal path's edge running to 1704 px and staying.
start-window.csv: `measure_swipe.ps1`'s Start window samples (`tick,pid,hwnd,visible,cloaked,left,top,right,bottom`) at the ~16 ms this host's 15.6 ms timer quantum allows, although the tool asks for 8 ms. The rect is the Start window, not the XAML island: on this layout the island sits inside it, which is the 95 px error the anchor note in docs/limits.md refers to.
