# tools/

screenshot.ps1: full-screen PNG in physical pixels; switches the process to per-monitor-v2 DPI awareness first, otherwise 200% scaling captures only the top-left quarter.
make_store_mods.ps1: generates the self-contained shipping source into the ignored `dist/<profile>/` — two profiles. `store` (default) is the submission: inlines `swipe_ipc_shared.h` at its `#include "..."` site inside a `#pragma clang diagnostic push/ignored "-Wunused-const-variable"/pop` pair, drops `-I`/`-Wall`/`-Wextra` from `@compilerOptions`, adds `@github`/`@license`/`@homepage`, then runs `windhawk-cli source meta --strict` and fails on any rejection. `local` is what `install_mods.ps1` installs: the same inlined headers, `-I` removed but `-Wall -Wextra` kept, no store metadata. Both profiles replace the `==WindhawkModReadme==` body with `README.md`, a `---` separator and `README.zh-CN.md`, and fail if either guide or marker is missing; the condensed block in `mods/` is never shipped. One mod ships, so one output per profile; there is no companion note and no second file. The CLI is a `-CliPath` override, then `windhawk-cli` on PATH, then `%ProgramFiles%\Windhawk\windhawk-cli.exe`. Never hand-edit its output: `docs/store.md` records the difference from `mods/`, the local flow and the pre-PR checks.
install_mods.ps1: the local install. Runs `make_store_mods.ps1 -Profile local`, installs `local@swipe-for-10start` with `mod install --file` + `mod enable`, and restarts `StartMenuExperienceHost.exe` unless `-SkipRestart`; `-All` adds the three diagnostic probes from `mods/`, `-Compiler` overrides the CLI from the same path-then-`%ProgramFiles%` lookup, and the failure message names both locations. One `id version enabled|failed` line per mod; any failed install or compile exits non-zero. It needs an elevated shell: the engine's compiled-mod folder is ACL'd, so `mod install` fails with "the folder for compiled mods is not writable" (hint: run as administrator). The same compile without elevation is `windhawk-cli --app-root <a portable windhawk.ini pointing at a writable AppDataPath> mod install --file dist/local/swipe-for-10start.wh.cpp`, which is the gate every change in this repository is built through before it is deployed.
smoke.ps1: the one-pass regression smoke for the shipping mod — a VK_LWIN tap opens and closes, an injected edge pull opens, an injected panel drag closes, a click on the desktop closes, and three mixed-trigger rows interrupt a Win close with a desktop click, a Start-button close with a Win press, and a gesture close with a desktop click — each step judged by `start_menu.ps1`'s state plus the decision/executor lines written during that step, and the last step fails on any error-shaped line in either log (`renderer.log` and `bridge.log`). It judges the mod's trace, so it requires the `DiagnosticTrace` setting: after the first trigger it checks that `renderer.log` or `bridge.log` was written since the run started, and if neither was it prints `windhawk-cli mod settings set local@swipe-for-10start DiagnosticTrace=true` (run from an elevated shell) and exits non-zero. Its `-Log` default is the standard store's `renderer.log` built from `%ProgramData%` under `local@swipe-for-10start`, `-BridgeLog` defaults to `bridge.log` beside it, and a missing file is tolerated until that check because enabling the trace at runtime writes no line by itself. A run started on a cold executor (right after an install, or a reload with no recorded launcher thread) first performs one native open and its close, before any row: the executor window does not exist until the shell's own `Show` creates it, and that documented first-press pass is not a row. It sets PMv2 DPI awareness and reads the layout from the mod's own lines **after** the first row's Win open, keeping only lines at or after the run's tick mark so a rotated trace or an earlier session cannot supply historical coordinates. The axis, panel rectangle and band come from one `reveal panelTrail` record (accepted or rejected) — the newest line that carries all three — and any fallback field is accepted only from a record that has no axis or the same axis. The scale is the taskbar rectangle's physical thickness over half the band in DIP, kept fractional (1.25/1.5/2) so the physical coordinates it hands the injector stay inside the band and the panel on any taskbar edge, and the thickness is read only from a `dismiss` record whose axis matches the run's, using that record's own axis for the dimension: a historical bottom record cannot turn the screen width into a left-bar thickness, and a rotated log with no matching record leaves the scale missing rather than guessed. All four fields — axis, band, panel rectangle and scale — must have been measured in this run before it injects; otherwise the two touch rows fail with `layout incomplete: <fields>` instead of using a default. Every mark is `GetTickCount64` and every read re-opens the log and keeps the lines at or after it, because the trace rotates at its line cap and a line index would skip the new file's lines. A row requires the pair it claims, not a substring: the Win open is `intent recv ... kind=open trigger=win` plus the executor's ack for the exact show sequence the Start side published, and the Win close is `intent recv ... kind=close trigger=win` plus the executed method-1 dismiss; the touch open is `reveal pull qualified` plus the executor's ack for the exact show sequence; the drag close is its producer line (`close dismiss kind=...` or `close accepted ... kind=dismiss` for a digitizer, the click-away decision and its `method=7` intent for the injected pointer) plus the executed dismiss for that sequence, and the producer is named in the row (`producer=hid` or `producer=injected-pointer`); the click-away is `own toggle decide trigger=clickaway ... kind=close`, its intent, the matching method-6 dismiss and `win close observed`, so a native method-7 close fails it; a pull that starts inside the previous close's settle is judged by the reopen lines it produces, not by a fresh admission. The three interruption rows require the reopen decision (`kind=open dir=2`), the
cancel (`exec cancel request target=... reason=open-intent` or `close dismiss
cancelled kind=...`), `close ended ... reason=open-cancel`, no `win close
observed`, a cancellation `from=` below 1, and a final cloak read after that
close's own dismiss deadline (`executeAt` or the gesture settle end + 30 ms); the
row detail reports the interrupting producer, `from=` and the deadline. A click
row skipped by `-SkipClickAway` — the standalone click-away and both reversal
rows — is not added as a passed row: the run prints `skipped: ...` for it. It waits for the executor's `exec visible ... visible=visible` before clicking away, because a click inside the window's presentation (state 1/3) is swallowed on purpose, and it uses the VK_LWIN tap rather than `-EnsureOpen` because a bar that auto-hides cannot be opened through UIA. The Start-button row finds the taskbar button through `winapp ui search StartButton` (the same tool `start_menu.ps1` uses), hovers the dock edge to reveal an auto-hidden bar, and clicks its rectangle. The producer of an injected drag is not fixed: this build produced the real HID close, other runs produced the pointer-derived click-away, and the row names which one it saw; a `producer=hid` row from an injection is not quoted as a field measurement.
start_menu.ps1: reports or forces the legacy Start menu's open state through `DWMWA_CLOAKED` (`IsWindowVisible` stays TRUE while it is hidden); `-EnsureOpen` invokes the taskbar's Start button (`winapp ui invoke "开始" -a explorer --type Button`) up to three times at 1800 ms, which cannot open an auto-hidden taskbar — on this host all three left the menu cloaked — while a `VK_LWIN` tap opens it and the `START hwnd=... cloaked=... open=...` line reports it correctly; `-EnsureClosed` is one `VK_LWIN` tap.
touch_common.ps1: the one injection lifecycle every tool dot-sources. It owns DOWN, UPDATE, the 5 ms keep-alive, the serialised UP and the DPI setup; `End-Contact` owns stop, join and UP in that order, so no UPDATE can follow the release, and it records the UP timestamp (`ReleaseMs`) immediately before the injection. Two failures keep the contact open instead of pretending it ended: a join that times out sends no UP, and a failed UP leaves `ReleaseMs` at 0 and reports it, so a caller can see that no release happened and retry the UP. `touch_hold.ps1` and `follow_hold.ps1` call `End-Contact` alone, so a failed stop cannot skip the UP through a separate call. The 5 ms interval is below the mod's 18 ms idle release, so an injected hold reads as a finger.
inject_swipe.ps1: one-finger swipe through `InjectTouchInput` via `touch_common.ps1`, physical pixels; `-DryRun` prints the sequence without injecting. `frameId` stays 0 and the raw/himetric points stay zero or the sequence is rejected.
touch_hold.ps1: drag to a point, hold with the shared 5 ms keep-alive, capture, then release with `-ReleaseAtEnd`; `-Lift` is an alias of it, kept for existing calls. The keep-alive runs through the capture, so the screenshot is a live mid-gesture frame; without `-ReleaseAtEnd` the contact stays down until this process exits, because a later process cannot lift it.
follow_hold.ps1: the same capture, for the reveal follow from the screen edge; it keeps the shared 5 ms keep-alive running while the screenshot is taken. The virtual digitizer goes silent during a plain hold, so a live hold needs that keep-alive — `touch_hold.ps1` starts the same one, so either tool can photograph a mid-gesture state.
inject_swipe_holds.ps1: swipe with pauses at waypoints; each pause is a real hold through `touch_common.ps1` (one UPDATE every 5 ms), not 50 ms of silence.
measure_swipe.ps1: samples the Start window rect while a swipe runs and writes `artifacts/start-window.csv`; it asks for 8 ms, and this host's 15.6 ms timer quantum delivers ~16 ms. An earlier investigation helper, it captures no pixels.
probe_cursor_follow.ps1: opens Start with `VK_LWIN`, injects a drag through `touch_common.ps1` and polls `GetCursorPos`/`GetCursorInfo` from a background thread; writes `artifacts/cursor-follow.csv` and restores the saved cursor position.
ipc.ps1: the read-only view of the merged mod's channel. `-State` connects to `Local\SwipeFor10Start_SingleMod5_State` and prints the records' counters and values (open generation, intent and its ack and the `intentTaken` claim, executor command and its ack with the outcome and visibility names beside the numbers, controller direction and touch, peer tick and state, the peer activation epoch, its pid and UI thread, and `execCapable`). The debug command publisher is gone: the record, the mutex and the command event do not exist, and a position argument is refused. The read requires `initState == ready` (2) plus this header's magic (`0x53333053`) and `layoutBytes` (240), so a section that is still initialising or foreign is refused instead of misread; there is no version word, because the object namespace is the ABI identity (the `5` marks the 240-byte layout and the `Capability` event). An interrupted record leaves its seqlock counter odd: `-State` prints that record as `unstable` and no reader accepts the half-written line. Its byte offsets are the `offsetof` asserts in `mods/swipe_ipc_shared.h`.
native_flyout_frames.ps1: captures the native Quick Settings flyout (`Win+A`) as BMPs at ~10 ms with a reused DIB, and polls `IsWindowVisible` on `ControlCenterWindow` every 1 ms as t=0 (`DWMWA_CLOAKED` stays 0 for that window). The default prefix is `%TEMP%\qsa`, not a user-specific path. Each `t` is stamped immediately before its `BitBlt` and the copy's cost is written next to it as `cap=`. At capture time the taskbar was on top, so the flyout is anchored top-right and unfolds downward; the machine now runs the bar docked on the left, so a fresh capture is a different layout and the numbers in `artifacts/` remain the top-taskbar run.
native_flyout_track.py: fits each captured frame's vertical offset against the settled frame (Pearson r over the card interior) and prints the `t -> dy` table the settle fit consumes.
fit_settle_spring.py: models the shipped settle against `artifacts/native-flyout-open.csv`: slowest-root duration, end-value normalisation, the shipped damping by default, `--damping` to evaluate another and `--fit` to search. `--model legacy` repeats the old free-period fit whose 5/(zeta*omega) duration is wrong for an overdamped spring. It prints the residuals and states that the captured data does not identify the damping; y0 = 0 throughout. The half-open release line prints the initial tangent (`velocity * 10 ms`) and labels it a straight-line extrapolation, then prints the model's first sampled frame and its interpolated 10 ms position, so the tangent is not read as a position on the curve.
settle_track.ps1: pulls the menu half open from an edge, holds, releases, and tracks the panel's bottom edge for 500 ms by diffing each frame against a closed-menu baseline. Its geometry is the top-taskbar layout: default `StartY` 12 and a scan band of y 400..1419 physical, so on the live left docked bar neither the start point nor the scan band applies — it tracks the panel's bottom edge, which on a left bar is the wrong edge. Rework it for a side bar before using it there. Each frame stamps `t` before its `BitBlt`; its t=0 is the timestamp `End-Contact` takes immediately before the UP, not the end of the preceding capture.
panel_edge_track.ps1: samples the panel's visible trailing edge in physical pixels during a Win open or close, by diffing every frame against a closed-menu baseline — one thin strip through the panel (63 sampled lines out of one reused DIB, 32-96 px thick, its centre 15% of the panel's extent across the scan axis from the far corner, so it misses the injected finger at the middle), each `t` stamped immediately before its `BitBlt`, the extreme changed coordinate reported as `edge=` beside `progress=`. The axis is the mod's own `dismiss axis` (0 left, 1 top, 2 right, 3 bottom) and the tool derives the dock from it: the trailing edge is the panel's right/bottom/left/top side, `trail * scale` is the fully-open edge on every dock, and the panel becomes visible at the band's midpoint, the bar's inner edge (the work area's edge on a docked bar; one bar thickness inside it on an auto-hidden bar, whose work area reaches the screen edge). `EDGES` prints that fully-open edge, that visible entry and the work area's own entry with the progress at each; the strip runs from the entry to 8 px past the fully-open edge, so it stays out of the taskbar, and the measured fully-open extreme is the max changed coordinate on left/top and the min on right/bottom. `ANCHOR` compares it with `trail * scale` (8 px) and, on an uninterrupted win-tap close, the entry extreme with the band midpoint (3% of the travel); a run with a `pull` trigger is exempt because the pull is meant to reverse before the entry. Geometry is the run's own, never this file's: axis, rectangle, band and work area from the newest `reveal panelTrail` line at or after the run mark (an accepted record wins over a rejected one), `Distance` from the matching `gesture geometry axis=... dist=` line, and the scale from the `dismiss` bar thickness over half the band (smoke.ps1's source) cross-checked against the screen/work-area extent; a missing field refuses the run, and the derived edges must lie on the side `dir` names or the run is refused. The closed baseline is taken after `-CooldownMs`: an auto-hidden bar can still be sliding down after the close, and a baseline captured mid-slide fails its own verify frame. Progress is the mod's own `RevealProgressDip` mapping `1 - (edge - trail) / (dir * distance)` with dir -1 on left/top and +1 on right/bottom, printed with the numbers it used. `-WinTap` (default) taps VK_LWIN, taps again `-CloseAtMs` later and samples the whole close; `-Observe` samples a caller-triggered window; both accept `-TriggerAtMs`/`-Trigger` pairs (`pull`, `wintap`), measured from the close tap in win-tap mode and from the first sample in observe mode, and the pull is the shared 25 DIP band pull with a real release through `touch_common.ps1`. The Start window's cloak is the only open/closed source: a menu found open is closed before the warm-up and again when a run refuses after its own open, and the state at exit is printed. It cannot see the panel on the bar's side of the band midpoint or after the cloak — those samples are `edge=-1`, never progress 0, and the visible series stops at the entry (progress 0.363 on the live bottom auto-hidden layout, 0.278 on the left docked one); a bar edge that appears after the close can hold the last samples at the entry with no panel motion, and a frame can lag its stamp by one compositor interval. Verified on this machine on the live bottom auto-hidden layout only (2026-11-21: trail 279 DIP, band 804..900, work 0,0,1440,900, distance 900 DIP, scale 2 → open 558 px, entry 1704 px, work entry 1800 px; a plain `-WinTap` reached `at-close=558` and retracted 558→1704, and a pull at close+150 ms reversed at 709 px and ended at 558 px with the menu open); the left, top and right docks use the same derivation (the left work edge is the band midpoint); all four sides are checked by hand, and the numbers above are the bottom auto-hidden run.
